## 强制原则

凡是涉及 Amazon 广告优化、关键词动作、竞品投放、预算、竞价、否词、活动结构、自然排名、ACOS/TACOS 诊断或生命周期策略，必须先读取当前会话实际使用的 `amazon-ads-keyword-strategy` Skill，再给出建议。不得在未读取 Skill 的情况下，使用模型通用记忆、个人经验或单篇讲义直接给出广告优化动作。

Skill 是决策约束和证据路由的第一入口，不是唯一数据来源。读取 Skill 后，仍需按其中的 References Map、来源状态规则和实时数据 MCP 门槛获取必要资料。

## 执行顺序

1. **加载入口**：读取当前运行环境实际选中的 `SKILL.md`，确认 `name`、版本/修改时间（可获得时）和加载路径。
2. **识别任务**：判断是广告诊断、关键词库、竞品、预算/竞价、排名、生命周期、来源审查还是非业务任务。
3. **加载相关参考**：只加载该任务所需的 References Map 文件，例如指标、搜索词、活动结构、冲突、案例、来源审查或 MCP 决策门槛。
4. **提取约束**：列出产品阶段、目标、毛利、预算、样本量、库存、关键词角色、案例状态和禁止动作；保留 `disputed`、`unresolved`、`unsupported`、`outdated`、`context_dependent` 边界。
5. **获取数据**：若任务依赖当前市场、竞品、关键词、趋势、排名或放量，执行 `references/24_live_market_data_mcp_decision_gate.md`；账户级判断同时核对用户报告。
6. **交叉验证**：平台功能/政策查 Amazon 官方资料；讲义和案例只按 Skill 标记作为条件化证据，不把案例改写成通用规则。
7. **形成建议**：只有完成前述步骤，才能给当前优先测试路线；写清替代路线、风险、成功指标、停止指标和 7/14/30 天复盘窗口。

## 加载范围

### 广告业务任务

至少读取：

- 当前 `SKILL.md`；
- 与问题直接相关的 reference；
- 命中的 claim/case/conflict 记录；
- 若涉及实时市场事实，再读取 `24_live_market_data_mcp_decision_gate.md` 并调用 MCP。

### 来源审查或 Skill 维护任务

仍应先读取 `SKILL.md`，但可按来源审查协议工作；这类任务不需要为了回答文件结构问题强行调用市场 MCP，也不应虚构广告诊断结论。

### 纯数学或非业务任务

可以标记 `Skill 使用状态: NOT_REQUIRED`，但只在确实不产生广告优化建议时使用。若回答中出现任何广告动作、关键词判断或平台策略，必须回到 Skill-first 流程。

## 状态和失败处理

每个广告优化回答必须显示：

```text
Skill 使用状态: LOADED | PARTIAL | BLOCKED | NOT_REQUIRED
Skill 路径: <当前实际加载路径>
已加载参考: <文件名列表>
应用约束: <阶段/目标/数据/证据状态/禁止动作>
```

- `LOADED`：当前 Skill 入口和相关参考已读取，且能追溯到本次建议。
- `PARTIAL`：入口已读，但相关 reference、案例或数据仍缺失；只能给条件化建议、诊断问题或可逆测试。
- `BLOCKED`：Skill 文件不可读、当前安装副本不明确、版本冲突无法解决或工具链无法加载；不得给广告优化强动作，应先解决加载问题。
- `NOT_REQUIRED`：只限于不产生广告优化建议的纯数学、结构、来源或维护说明。

如果仓库 Skill 与 Codex 安装副本内容不同，优先使用当前会话实际触发的副本，并报告路径和差异；不能默认为两份内容一致。发现安装副本过期时，应提醒同步，但在同步前仍不得跳过当前可读取 Skill 的约束。

## 回答要求

建议开头或决策前先显示 `Skill 使用状态`。回答必须能回答：

- 使用了哪一个 Skill 入口和哪些 reference；
- 哪些建议来自 Skill 的 executable rule，哪些只是诊断假设、案例相似性或条件化 claim；
- 哪些数据来自用户账户、MCP、Amazon 官方资料或讲义；
- 是否存在缺失数据、证据冲突、过时功能或不适用条件；
- 当前路线为何优先，何时停止，备用路线是什么。

不得用“行业一般都这样”“我建议直接……”替代 Skill 中规定的证据、条件和验证流程。

## 边界

- Skill-first 不等于只看 `merged_rules.jsonl`；案例、冲突、未决主张和来源验证层仍必须按问题读取。
- Skill-first 不等于讲义是真理；原始资料仍按来源审查协议交叉验证。
- Skill-first 不等于 MCP 已验证；实时数据仍需按 `COMPLETE/PARTIAL/BLOCKED/NOT_REQUIRED` 记录。
- 不能因为用户要求“直接给结论”而跳过 Skill、数据完整性检查或合规边界。
