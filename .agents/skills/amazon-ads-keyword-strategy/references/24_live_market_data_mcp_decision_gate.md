## 目的

用户已在 Codex 中安装西柚洞察 MCP。对需要当前市场、竞品、关键词或趋势事实的广告决策，先调用该 MCP 获取相关数据，再提出动作。MCP 是实时市场证据层，不是讲义真伪裁判，也不替代 Amazon 官方政策/功能文档、用户账户报告或项目内部证据。

## 何时必须调用

下列任务在给出“应该提价/降价/加预算/否词/拆活动/投竞品/选择关键词/判断排名机会”等决策前，必须调用西柚洞察 MCP：

- 评估市场需求、搜索趋势、季节性、类目竞争或市场容量；
- 评估竞品 ASIN、价格、评分、评论量、BSR、库存/可售性、变体或竞品投放机会；
- 选择、排序、扩展或否定关键词，判断搜索量、竞争度、相关性、词频、排名或竞品覆盖；
- 判断自然排名、广告排名、市场份额、搜索词机会或放量空间；
- 需要比较多个市场、站点、类目、ASIN 或时间窗口的当前状态；
- 用户提供的讲义、截图或旧报告包含需要现场数据验证的阈值或结论。

以下情况可以标记 `NOT_REQUIRED`，不强制调用市场 MCP：纯数学推导、文件/Skill 结构审查、来源审查本身、只复述已给出的账户表格、政策文本核对（仍需 Amazon 官方来源）以及不产生业务动作的概念解释。

## 数据选择

先根据决策类型确定最小必要数据，不要无目的抓取大量数据：

| 决策 | 至少优先获取 | 可选补充 |
|---|---|---|
| 关键词扩展/排序 | marketplace、类目/商品、关键词、搜索量或趋势、竞争/相关性、数据日期 | 竞品覆盖、自然/广告排名、点击或转化代理指标 |
| 否词/保留词 | 关键词/搜索词、相关性、搜索量/趋势、竞品或类目语境 | 用户搜索词报告中的点击、订单、花费、归因窗口 |
| 竞品投放 | 竞品 ASIN、价格、评分、评论量、类目/属性、可售性、近期趋势 | 变体、优惠、详情页差异、关键词重合 |
| 加预算/放量 | 市场需求趋势、竞争强度、目标词/竞品机会、季节性 | 用户账户预算消耗、边际订单、库存和毛利 |
| 排名诊断 | 目标关键词当前市场/竞品状态、趋势、竞争度 | 用户自然排名、广告单占比、TACOS、库存和价格 |
| 市场/站点比较 | 每个 marketplace 的同口径需求、竞争、价格和时间窗口 | 汇率、履约、合规、库存和利润 |

MCP 返回的数据不能替代用户账户级广告报告。涉及 ACOS、TACOS、CVR、CPC、广告单占比或自然单占比时，必须同时标出哪些数字来自用户账户、哪些来自 MCP、哪些缺失。

## 调用和记录

### 调用原则

1. 先读取本 Skill 和本文件，识别决策所需字段。
2. 使用当前 Codex 会话实际暴露的西柚洞察 MCP 操作；不得猜测、虚构或硬编码不存在的工具名、字段名或返回值。
3. 查询必须带 marketplace/站点、ASIN 或关键词、类目（可用时）和时间范围；需要趋势时明确日/周/月粒度。
4. 对同一决策尽量使用同一站点、同一时间口径和同一筛选条件；比较时先检查字段定义是否一致。
5. 记录 MCP 返回的原始摘要或可复查标识，不把模型记忆或搜索结果冒充 MCP 数据。

### 最小数据调用记录

每次产生业务决策时，在回答中保留以下记录；若项目需要持久化，可写入专用 JSONL，不要覆盖原始账户报告：

```text
实时数据调用状态: COMPLETE | PARTIAL | BLOCKED | NOT_REQUIRED
数据提供方: 西柚洞察 MCP
实际操作名: <当前会话暴露的真实 MCP operation；未知时写 unknown>
调用时间: <Asia/Shanghai timestamp>
marketplace: <站点>
对象: <ASIN / keyword / category>
请求窗口: <from-to 和粒度>
返回窗口: <实际返回窗口>
筛选与口径: <filters、去重、排序、字段定义>
返回记录数: <count>
关键结果: <只写 MCP 实际返回的摘要>
数据新鲜度: <as-of / fetched-at / unknown>
缺失或错误: <字段缺失、权限、超时、站点不支持等>
```

不要在记录中写入不必要的买家个人信息、令牌、Cookie 或完整敏感账户数据。只保留完成决策所需的最小摘要。

## 决策闸门

### `COMPLETE`

所需的市场/竞品/关键词字段已由 MCP 返回，站点、对象和日期口径明确，且与用户账户数据或项目规则的边界已写清。可以给出“当前优先测试路线”，仍需说明置信度和可逆窗口。

### `PARTIAL`

部分字段返回，但关键字段缺失、口径不一致或数据新鲜度不足。只能给条件化方案、诊断假设或两条备选路线；不得把缺失字段补成推测值。

### `BLOCKED`

西柚洞察 MCP 未暴露、调用失败、无权限、无目标站点/ASIN/关键词或返回为空。不得给出依赖实时市场事实的强决策。应列出缺失数据，请用户补充或先提供数据采集方案；若必须推进，只能给低风险、可逆的诊断步骤并明确“未经过 MCP 数据验证”。

### `NOT_REQUIRED`

任务确实不依赖当前市场数据，例如数学、结构、来源或政策文本审查。说明为什么不需要 MCP；政策和平台功能仍按官方一手来源核对。

## 证据边界

- MCP 数据说明某个时间点或查询口径下“发生了什么”，不能单独证明广告因果、自然排名因果或所有类目都适用。
- MCP 的市场趋势、搜索量、竞品排名与讲义案例属于不同证据层；必须保留 `data_provider`、日期、站点和查询条件。
- Amazon 官方文档优先用于政策、功能名称、竞价入口、报告定义和当前平台机制；MCP 优先用于当前市场/竞品/关键词状态。两者冲突时分别呈现，不强行合并成一个结论。
- 项目 `merged_rules.jsonl`、案例库和讲义 claim 仍受原有状态、证据簇和 `讲义案例提示` 规则约束。MCP 新数据不能自动把 `unsupported`、`disputed` 或 `context_dependent` 主张升级为通用规则。
- 若 MCP 返回值与用户账户报告冲突，先检查站点、日期、归因窗口、商品/变体、币种、去重和字段定义，再标记 `disputed` 或 `unresolved`；不要静默选择较符合讲义的一方。

## 回答格式

涉及实时市场数据的回答必须在决策前或决策附近出现：

1. `实时数据调用状态`；
2. MCP 查询对象、站点、请求/返回窗口和数据新鲜度；
3. MCP 实际返回的关键结果与缺失字段；
4. 与用户账户数据、Amazon 官方资料和项目 Skill 规则的边界；
5. 当前优先路线、备选路线、风险、成功指标和停止指标；
6. 若命中讲义案例或条件化主张，同时显示 `讲义案例提示`。

“MCP 已调用”不等于“结论已证明”。只有数据覆盖决策所需字段且口径一致时，才可使用 `COMPLETE`。

## 常见错误

- 只调用一次 MCP 就把结果当成长期市场真相；
- 不带 marketplace、日期或 ASIN/关键词，导致不同对象被混比；
- 用 MCP 搜索量替代用户账户的点击/订单/CVR；
- 把竞品排名或搜索量直接解释成自然排名因果；
- MCP 失败后仍给出“必须提价/必须否词/必须加预算”的强动作；
- 虚构 MCP 工具名、字段、数据日期或返回数值；
- 把 MCP 数据写进 `merged_rules.jsonl` 而不保留查询条件和时间边界。
