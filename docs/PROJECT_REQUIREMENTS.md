# 项目长期协作要求

## 1. 项目目标

将本仓库维护为一个可持续演进、证据可追溯的 Amazon 广告与关键词策略 skill。Codex 的职责不是照抄讲义，而是把资料转化为带条件、证据、置信度、限制和验证方法的决策支持。

## 2. 文档职责

| 文件或目录 | 职责 |
| --- | --- |
| `AGENTS.md` | Codex 在本仓库工作的强制协作规则。 |
| `.agents/skills/amazon-ads-keyword-strategy/SKILL.md` | agent 执行业务任务的主入口。 |
| `.agents/skills/amazon-ads-keyword-strategy/references/` | 方法、schema、业务规则和来源验证协议。 |
| `data/raw/` | 原始证据；默认只读，不静默修正。 |
| `data/processed/amazon_ads_skill/` | 可重建的索引、提取、规则、案例、冲突和报告。 |
| `docs/CODEX_HANDOFF.md` | 下一次 Codex 首先读取的当前状态。 |
| `docs/handoffs/` | 每次任务的历史交接记录。 |

当内容冲突时，执行优先级为：当前用户明确要求 > `AGENTS.md` > `SKILL.md` > 相关 reference > 历史交接。历史交接只描述状态，不得覆盖当前规则。

## 3. 每轮工作流程

1. **接管**：读取入口文件、最新交接和 Git 状态。
2. **界定**：写清目标、范围、阶段、禁止事项、输入和验收标准。
3. **调查**：定位现有实现、数据产物和相关历史决定，不凭文件名猜测。
4. **执行**：做最小必要修改，保持原始来源与派生结论分离。
5. **验证**：运行相关检查，记录命令、结果和未运行项。
6. **同步**：行为、schema 或规则变化必须同步相应文档和 eval。
7. **交接**：更新滚动交接和一份历史记录后再宣布完成。

## 4. 新讲义和文件的处理要求

每次收到新资料时：

1. 建立来源记录：文件名、来源、作者/机构、发布日期、获取日期、版本、适用站点/广告类型、是否一手来源。
2. 保留原件，计算稳定标识或哈希；重复文件不能当成独立证据增加权重。
3. 把重要说法拆成原子主张，保留原文位置与上下文。
4. 将每条主张与以下范围交叉验证：
   - 本项目全部相关 raw/processed 记录；
   - 用户在本项目提供且被纳入范围的全部资料；
   - 现有规则、案例、冲突登记和反例；
   - 对时效敏感或平台事实类主张，核对当前 Amazon 官方一手资料；
   - 若有账户实测数据，区分实测观察与平台通用机制。
5. 输出来源覆盖表。未被纳入、无法读取、图片无法识别或缺页的资料必须列出，不能假装已检查。
6. 根据 `references/14_source_validation_and_conflict_protocol.md` 标记判断状态。

“多数讲义都这样说”不等于事实。多个资料若互相转载、共同引用同一来源或重复同一无证据观点，应视为一个证据簇，而不是多个独立证据。

## 5. 错误与不确定性的表达

- 只有当主张与更高等级且适用范围一致的证据直接冲突，或可复现数据证明不成立时，才标为 `confirmed_error`。
- 平台规则后来变化时标为 `outdated`，不要把历史上曾正确的内容简单称为错误。
- 缺少证据标为 `unsupported`；不能仅凭缺证据断言错误。
- 结论随产品阶段、类目、目标或样本变化时标为 `context_dependent`。
- 可靠来源仍有冲突时标为 `disputed`；证据不足时标为 `unresolved`。
- `disputed` 和 `unresolved` 的观点全部保留。实际回答必须说明不同做法、各自条件、风险、所需数据和建议测试。

## 6. 完成定义

任务只有同时满足以下条件才算完成：

- 请求范围内的工作真实完成；
- 相关验证已运行并如实记录；
- 规则/行为变化已同步文档与 eval；
- `docs/CODEX_HANDOFF.md` 已更新；
- `docs/handoffs/` 已新增本轮记录；
- 未决风险和下一步入口清晰；
- 没有把未运行、未核实或被阻塞内容写成完成。
